### Намір
Змоделювати дані системи обліку інвентаря настільних ігор (див. README.md). Правила гри не моделюються.

### Сутності та атрибути
- User(Користувач): id, username
- Game(Гра): id, name, description
- ItemCatalog(Каталог предметів): id, name, description
- Item(Предмет): id, name, description
- InventoryPosition(Позиція інвентаря): quantity(ціле число)
- Character(Персонаж): id, name

Усі id є UUID(на діаграмі string). Усі інші атрибути за замовчуванням є текстовими, якщо інше не вказано явно. 
Ключем InventoryPosition є пара Персонаж-Предмет.

### Зв'язки
- Користувач може бути власником багатьох ігор, гра має одного власника (1:N)
- У грі може бути 0 або багато персонажів, але персонаж є частиною лише однієї гри (1:N)
- У користувача може бути 0 або багато персонажів, але персонаж належить лише одному користувачу (1:N)
- Гра може ссилатися на 0 або декілька каталогів, декілька або 0 ігор можуть використовувати один каталог (N:M)
- Один предмет може належати одному каталогу, в одному каталозі може бути 0 або багато предметів (1:N)
- Користувач може створити 0 або багато каталогів, в одного каталога може бути лиже один власник (1:N)
- Позиція інвентаря може мати тільки один предмет, але один предмет може належати 0 або багатьом позиціям (1:N)
- Персонаж може мати 0 або багато позицій, але позиція може належити лише одному персонажу (1:N)

### Правила домену
- Для пари персонаж-предмет існує не більше однієї позиції інвентаря
- Предмет у позиції інвентаря належить каталогу, на який ссилається гра персонажа якому належить позиція
- InventoryPosition.quantity >= 1

### Критерії прийняття
- Для кожного зв'язку вказана кардинальність
- Відсутність сутностей-зв'язків без значущих атрибутів
- Усі назви на діаграмі збігаються з цим файлом(окрім тих що випливають зі зв'язків)
- Діаграма є читаємою
- Типи id є узгодженими
- Відсутність обчислюємих атрибутів
- Третя нормальна форма
- Вказані FK
